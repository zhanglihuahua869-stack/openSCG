## 背景说明

当前项目 `openscg_app` 的 Docker 构建流程使用 `npm install`，且仓库中缺少 lockfile，导致在 Docker Compose 构建阶段经常长时间停留在依赖安装与 reify 阶段，构建过程可重复性和可观测性都较差。

本次调整目标是将 Docker 镜像构建流程切换为 `pnpm`，引入 `pnpm-lock.yaml`，降低依赖解析不确定性，并改善后续构建稳定性。

## 涉及文件清单

- `openscg_app/Dockerfile`
- `openscg_app/pnpm-lock.yaml`
- `doc_plan/CHANGELOG.md`

## 具体改动计划

1. 在 `openscg_app/Dockerfile` 中启用 `corepack`，统一使用 `pnpm` 作为容器内包管理器。
2. 将构建阶段和运行阶段的依赖安装命令由 `npm install` 改为 `pnpm install --frozen-lockfile`。
3. 保留 `PUPPETEER_SKIP_DOWNLOAD`，避免 Docker 构建阶段下载 Puppeteer 浏览器二进制。
4. 在项目中生成 `openscg_app/pnpm-lock.yaml`，让 Docker 构建基于 lockfile 做确定性安装。
5. 验证 `docker compose build --progress=plain --no-cache` 是否能够正常推进到 `pnpm` 安装阶段并输出清晰日志。

## 预期风险点

1. `pnpm` 的依赖布局与 `npm` 不同，若项目中存在依赖提升假设，可能暴露潜在兼容性问题。
2. 运行阶段使用 `pnpm install --prod` 时，若服务启动隐式依赖 devDependencies，可能导致容器启动失败。
3. 若网络环境本身不稳定，切换到 `pnpm` 后仍可能遇到 registry 请求超时，但 lockfile 能降低解析阶段的不确定性。
