# 项目分析与原理说明

## 1. 项目主要内容 (What is the project about?)
OpenSCG (Open-Source Cardiac Graph Infrastructure) 是一个开源的远程医疗基础设施项目。它的核心目标是将普通的智能手机变成一个实时的心震图（SCG, Seismocardiography）传感器。通过这个系统，患者无需购买额外的硬件设备或安装专门的 App，只需在手机浏览器中打开网页（PWA），将手机放在胸前，医生即可在远程问诊时通过网页实时观察到患者的心跳波形（机械振动）。

## 2. 使用的原理 (Underlying Principles)
项目基于 **心震图 (Seismocardiography, SCG)** 原理：
心脏在跳动时（收缩和泵血），会产生微小的机械振动并传导至胸壁。现代智能手机内部配备了高灵敏度的微机电系统（MEMS）传感器。当手机平放在胸骨中部或心尖位置时，手机内的传感器能够感知并记录下这些随着心跳产生的微小线性位移和振动。系统通过采集这些振动数据，即可绘制出反映心脏机械活动的波形图。

## 3. 陀螺仪与加速度计是什么 (Gyroscope & Accelerometer)
它们是智能手机中内置的两种关键运动传感器：
- **加速度计 (Accelerometer)**：主要用于测量设备在三个空间轴（X、Y、Z）上的线性加速度（即速度的变化率）以及重力的方向。在本项目中，它是**最核心**的传感器，负责捕捉胸腔由心跳引起的微小上下/左右震动。
- **陀螺仪 (Gyroscope)**：主要用于测量设备围绕三个空间轴（俯仰 Pitch、横滚 Roll、偏航 Yaw）的旋转角速度。虽然心脏跳动主要产生线性位移（由加速度计测量），但有时也会引起胸部的微小扭转或倾斜（称为陀螺心震图 GCG），陀螺仪可以用来辅助采集这些旋转维度的机械振动数据。本项目前端主要通过 Web API `DeviceMotionEvent` 统一获取这些设备的运动信息。

## 4. 如何实现与流程 (Implementation Steps & Flow)

### 技术栈
- **前端与服务端**：Next.js 15 (App Router), React 19, Tailwind CSS
- **实时通信**：Socket.io (WebSockets)
- **状态与缓存**：Redis (用于高频数据缓冲与会话管理)
- **数据结构**：采用优化后的 V2 数据格式（如 `[timestamp_ms, acc_x, acc_y, acc_z]` 元组），以节省 60% 的网络带宽。

### 工作流程
1. **患者端 (采集)**：
   - 患者通过手机浏览器访问 PWA 应用，授权获取设备的动作与方向权限（必须在 HTTPS 环境下）。
   - 前端调用浏览器的 `DeviceMotionEvent` API (`useMotionSensor` Hook)，高频持续地采集手机传感器的 X/Y/Z 轴数据。
2. **数据传输 (流式通信)**：
   - 采集到的数据点组合成优化的 JSON 数组格式。
   - 前端通过 `Socket.io` 建立的 WebSocket 通道，将原始振动数据以极低延迟实时发送到 Next.js 自定义服务器。
3. **服务端 (缓冲与路由)**：
   - 服务器接收到 WebSocket 数据流，将其缓冲并存储到 Redis 中，同时广播给订阅了该会话的医生端。
4. **医生端 (可视化)**：
   - 专家/医生在浏览器中打开专属的 Session 链接。
   - 医生端前端同样通过 WebSocket 接收实时数据流，并利用前端组件（SignalViewer）将数值转化为直观的实时心跳波形图，供医生进行医疗参考。
