## 背景说明

当前 `openscg_app` 已切换到基于 `pnpm` 的 Docker 构建，但镜像构建阶段实际使用的是 `pnpm@11.0.8`。
原有配置仍通过 `package.json` 的 `pnpm.onlyBuiltDependencies` 声明依赖脚本白名单，该写法在 `pnpm 11` 中已废弃，导致 Docker 内 `pnpm run build` 前的依赖校验抛出 `ERR_PNPM_IGNORED_BUILDS`。

## 涉及文件清单

- `openscg_app/package.json`
- `openscg_app/pnpm-workspace.yaml`
- `openscg_app/Dockerfile`

## 具体改动计划

1. 在 `openscg_app/package.json` 中增加 `packageManager: pnpm@11.0.8`，固定 Docker 与本地的 pnpm 主版本行为。
2. 删除已废弃的 `pnpm.onlyBuiltDependencies` 配置，避免继续依赖 pnpm 10 的旧字段。
3. 新增 `openscg_app/pnpm-workspace.yaml`，使用 `allowBuilds` 显式放行 `esbuild`、`puppeteer`、`sharp`、`unrs-resolver` 的依赖脚本。
4. 调整 `openscg_app/Dockerfile`：
   - 安装依赖前额外复制 `pnpm-workspace.yaml` 进入镜像上下文。
   - 构建命令改为 `pnpm --config.verify-deps-before-run=false run build`，减少运行脚本前的二次依赖自检干扰。
   - 在运行阶段同步复制 `pnpm-workspace.yaml`，保证生产依赖安装与构建阶段使用相同 pnpm 配置。

## 预期风险点

- `puppeteer`、`sharp` 等依赖在 Alpine 镜像内若后续需要真实二进制能力，仍可能暴露系统库缺失问题；本次修改仅修复 pnpm 白名单配置不生效的问题。
- 当前 `Dockerfile` 仍固定复制 `next.config.mjs`，若项目后续只保留 `next.config.ts`，需要再同步清理运行时复制逻辑。
